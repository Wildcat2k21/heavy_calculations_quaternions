## 1. ИТОГ АНАЛИЗА: ПОЧЕМУ ПРОЕКТ НЕ ВПИСЫВАЕТСЯ В СТАНДАРТНЫЕ ТРАЕКТОРИИ

### 1.1. Суть проекта

Проект представляет собой **интерактивный исследовательский стенд** для сравнения двух математических моделей 3D-вращения:
- кватернионы (axis-angle → quaternion composition, WASM Rust)
- матрицы вращения (Rx / Ry / Rz, WASM Rust)

Стек: Rust → WebAssembly → React/Vite → Three.js/WebGL

### 1.2. Почему не подходит ни одна стандартная траектория

| Траектория | Причина несоответствия |
|-----------|----------------------|
| **А. Десктопная** | Java Swing/JavaFX + SQLite/PostgreSQL — стек кардинально другой; нет локальной БД; нет CRUD |
| **Б. Веб-ориентированная** | JSP/Servlets/Spring MVC — нет серверной части; нет REST API; нет БД |
| **В. Мобильная** | Android/Flutter/React Native + Java Backend — нет мобильного клиента; нет бэкенда |
| **Г. Enterprise** | Full Stack + REST + Docker — проект не является корпоративной системой |

### 1.3. В чём ценность проекта

Проект реализует **нетипичную для учебных работ исследовательскую задачу**:

- Доказывает преимущество нативного кода (WASM/Rust) над интерпретируемым (JS) для вычислений реального времени
- Реализует полноценный математический движок с нуля (Vec3, Quat, Mat3, парсер OBJ)
- Исследует сравнительную производительность математических моделей вращения
- Имеет коммерческую ценность как компонент для любого 3D-редактора или симулятора

## 4. ГЛАВНАЯ ТЕХНИЧЕСКАЯ ДОРАБОТКА: РЕЖИМ WASM vs РЕЖИМ ЧИСТОГО JS

### 4.1. Идея

Добавить в проект **режим работы без WASM** — реализовать те же операции вращения на чистом JavaScript. Это позволит:
- наглядно сравнить производительность в реальном времени
- снять измеримую метрику по обоим режимам
- получить центральный результат исследования

### 4.2. Что нужно реализовать

#### Шаг 1 — JS-fallback модуль

Создать `src/math/rotations-js.js` — реализация тех же функций, что есть в WASM, но на чистом JS:

```js
// Аналог rotate_vertices_axis_angle_inplace (WASM) — на чистом JS
export function rotateVerticesAxisAngleJS(vertices, ax, ay, az, angle) {
    const len = Math.sqrt(ax*ax + ay*ay + az*az);
    if (len === 0) return;
    const ux = ax/len, uy = ay/len, uz = az/len;
    const half = angle * 0.5;
    const sh = Math.sin(half), ch = Math.cos(half);
    const qw = ch, qx = ux*sh, qy = uy*sh, qz = uz*sh;
    for (let i = 0; i < vertices.length; i += 3) {
        const x = vertices[i], y = vertices[i+1], z = vertices[i+2];
        const uvx = qy*z - qz*y, uvy = qz*x - qx*z, uvz = qx*y - qy*x;
        const uuvx = qy*uvz - qz*uvy, uuvy = qz*uvx - qx*uvz, uuvz = qx*uvy - qy*uvx;
        vertices[i]   = x + 2*(qw*uvx + uuvx);
        vertices[i+1] = y + 2*(qw*uvy + uuvy);
        vertices[i+2] = z + 2*(qw*uvz + uuvz);
    }
}

// Аналог rot_by_rotmat_inplace — на чистом JS
export function rotByRotmatJS(vertices, angle, axis) {
    const cos = Math.cos(angle), sin = Math.sin(angle);
    for (let i = 0; i < vertices.length; i += 3) {
        const x = vertices[i], y = vertices[i+1], z = vertices[i+2];
        let nx, ny, nz;
        if (axis === 0)      { nx=x;          ny=y*cos-z*sin; nz=y*sin+z*cos; }
        else if (axis === 1) { nx=x*cos+z*sin; ny=y;          nz=-x*sin+z*cos; }
        else                 { nx=x*cos-y*sin; ny=x*sin+y*cos; nz=z; }
        vertices[i]=nx; vertices[i+1]=ny; vertices[i+2]=nz;
    }
}
```

#### Шаг 2 — Переключатель режима вычислений

Добавить в панель управления кнопку (или тоггл):

```
[WASM] / [JS]  — режим математического движка
```

В `WebGL/index.js` добавить флаг `engineMode: 'wasm' | 'js'` и использовать соответствующие функции в цикле анимации.

#### Шаг 3 — Панель метрик реального времени

Добавить оверлей поверх 3D-сцены с показателями:

```

FPS:       60
Кадр:      0.42 ms
Вершины:  12 840
```

Реализовать через `performance.now()` замер времени блока вычислений в цикле `animate()`.

#### Шаг 4 — Сессия бенчмарка

Добавить кнопку **«Запустить бенчмарк»**, которая:
1. Фиксирует текущее состояние (метод вращения, количество вершин)

4. Выводит сравнительную таблицу результатов прямо в UI

## 11. ПРИНЦИПЫ, КОТОРЫЕ НЕЛЬЗЯ НАРУШАТЬ

1. **Не трогать WASM-логику** — `rotation-core/src/lib.rs` и скомпилированный `.wasm` файл менять только по явной необходимости
2. **JS-fallback — отдельный модуль** — не смешивать с существующей логикой; переключение через флаг
3. **Не добавлять серверную часть** — проект работает как статический фронтенд; это его достоинство
4. **Сохранить inplace-парадигму** — JS-fallback обязан реализовать те же алгоритмы (inplace), иначе сравнение некорректно
5. **Математическая корректность важнее скорости разработки** — JS-реализация должна давать идентичный результат с WASM-реализацией (проверить на тестовых векторах)

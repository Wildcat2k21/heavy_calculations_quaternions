# Методология замеров

## Что измеряется

**Время блока вычисления вращения** за один кадр (в миллисекундах) — длительность
вызова функции вращения, применённой ко всем вершинам модели. Это единственная
часть кадра, которая **различается** между WASM и JS, поэтому именно она —
предмет сравнения.

Из замера **исключены** (одинаковы для обоих движков и не относятся к движку):

- сброс рабочего буфера `workingVertices.set(baseVertices)`;
- передача данных на GPU (`positionAttr.needsUpdate`);
- рендеринг сцены Three.js;
- работа `OrbitControls`.

В измеряемый блок WASM-пути **включён** маршалинг `Float32Array` ↔ линейная память
WASM — это честная цена использования WASM.

## Инструмент

`performance.now()` — высокоточный таймер (доли миллисекунды). Вокруг вызова
вращения:

```js
buf.set(baseVertices);              // сброс (вне замера)
const t0 = performance.now();
rotate(angle);                      // ← измеряемый блок
times[f] = performance.now() - t0;
```

## Параметры сессии

| Параметр | Значение |
|----------|----------|
| Измеряемых кадров | **300** на каждое сочетание |
| Прогрев (warmup) | **30** кадров (не учитываются) |
| Сочетаний | **4**: {Кватернион, Матрица} × {WASM, JS} |
| Нагрузка кватерниона | поворот вокруг оси `(1,1,1)/√3`, угол свипуется `0…2π` |
| Нагрузка матрицы | поворот `Rx`, угол свипуется `0…2π` |
| Модели | `model.json` (50 970 верш.) и `model.h.json` (326 786 верш.) |

> «Вершины» здесь — элементы буфера отрезков (`len/3` = рёбра×2), т.е. реальное
> число точек, обрабатываемых за кадр.

### Зачем прогрев
Первые вызовы JS проходят интерпретацию/JIT-компиляцию, а кэши процессора ещё
«холодные». 30 холостых кадров стабилизируют замер, исключая выбросы старта.

### Зачем свип угла
Меняющийся угол не даёт движку/компилятору «схитрить» на константах и приближает
нагрузку к реальной анимации.

## Собираемые метрики

Для каждого сочетания по 300 кадрам:

| Метрика | Определение |
|---------|-------------|
| **Min frame time** | минимальное время кадра (мс) |
| **Max frame time** | максимальное время кадра (мс) |
| **Avg frame time** | среднее время кадра (мс) — основная метрика |
| **Avg FPS** | `1000 / Avg frame time` — теоретический потолок FPS по compute |
| **Speedup ×** | `Avg(JS) / Avg(WASM)` для одной модели вращения |

## Контроль корректности

После замеров стенд вычисляет `max |WASM − JS|` — максимальное покомпонентное
расхождение результата WASM и JS на одном кадре (угол `π/3`). Ожидается порядок
`10⁻⁵…10⁻⁶` (предел `f32`), что подтверждает: сравнивается **одна и та же
математика** (см. [hypothesis.md](../01-research-analysis/hypothesis.md), H3).

## Условия и оговорки

- FPS в **живом** режиме ограничен vsync (обычно 60), поэтому различающей метрикой
  служит **время кадра**, а не живой FPS.
- Во время бенчмарка живой расчёт приостановлен (`benchmarkRunning = true`), чтобы
  не конкурировать за CPU.
- Браузер уступает поток каждые 50 кадров (отзывчивость вкладки); на отдельный
  замер это не влияет — каждый кадр измеряется независимо.
- Абсолютные числа зависят от CPU, браузера и ОС — поэтому в отчёт записываются
  окружение и UA, а выводы делаются по **относительным** показателям (ускорение).
- **Квантование таймера.** Firefox по умолчанию округляет `performance.now()` до
  **1 мс** (`privacy.reduceTimerPrecision`), поэтому в собранных данных `Min = 0`
  и `Max` целочисленны. Среднее по 300 кадрам остаётся репрезентативным за счёт
  дизеринга квантования, но абсолютная точность ограничена — относительные выводы
  (ускорение, линейность) устойчивы. Для более тонкого замера: увеличить нагрузку
  (детальная модель), снять округление таймера или повторить в другом браузере.

## Формат экспорта

Стенд формирует готовый текстовый блок (кнопка «Копировать»):

```
=== BENCHMARK SESSION ===
Дата: …
Браузер/UA: …
Модель: …
Кол-во вершин (буфер, len/3): …
--- WASM / Кватернион --- … (Frames/Min/Max/Avg/FPS)
--- JS / Кватернион --- …
--- WASM / Матрица --- …
--- JS / Матрица --- …
--- КОРРЕКТНОСТЬ (max |WASM − JS|) --- …
--- УСКОРЕНИЕ WASM vs JS --- …
=========================
```

Этот блок переносится в [wasm-mode-results.md](wasm-mode-results.md),
[js-mode-results.md](js-mode-results.md) и [comparison.md](comparison.md).

# Математическая модель

Формализация двух сравниваемых моделей вращения. Обе реализованы идентично в Rust
(`rotation-core/src/lib.rs`) и JS (`src/math/rotations-js.js`).

## 1. Кватернионная модель

### Построение кватерниона из оси-угла

Дана ось `a = (aₓ, a_y, a_z)` и угол `θ`. Нормируем ось:

```
|a| = √(aₓ² + a_y² + a_z²),    û = a / |a|
```

Единичный кватернион поворота:

```
q = ( q_w, q_x, q_y, q_z ) = ( cos(θ/2),  ûₓ·sin(θ/2),  û_y·sin(θ/2),  û_z·sin(θ/2) )
```

### Поворот вектора (формула Родрига)

Вместо `v' = q·v·q*` используется эквивалентная форма через двойное векторное
произведение (меньше операций, та же суть). Пусть `u = (q_x, q_y, q_z)`:

```
t  = u × v
v' = v + 2·( q_w·t + u × t )
```

Покомпонентно (как в коде):

```
uv  = u × v
uuv = u × (u × v)
v'  = v + 2·( q_w·uv + uuv )
```

### Композиция нескольких вращений

Узлы вращения объединяются произведением кватернионов (порядок важен):

```
q_final = q₁ · q₂ · … · qₙ ,   затем нормировка
```

Реализовано в `buildResultQuaternion()`; результат переводится обратно в ось-угол
(`quatToAxisAngle()`) и применяется к вершинам единым вызовом ядра.

### Стоимость на вершину
≈ 2 векторных произведения + сложения/умножения ⇒ **≈ 15–20 арифметических
операций** на вершину (без учёта однократного построения кватерниона).

## 2. Матричная модель

Поворот вокруг одной координатной оси. При `c = cosθ`, `s = sinθ`:

```
Rx:  x' = x
     y' = y·c − z·s
     z' = y·s + z·c

Ry:  x' = x·c + z·s
     y' = y
     z' = −x·s + z·c

Rz:  x' = x·c − y·s
     y' = x·s + y·c
     z' = z
```

Последовательность узлов применяется как `v' = Rₙ·…·R₁·v`.

### Стоимость на вершину
**4 умножения + 2 сложения** на вершину (косинус/синус считаются один раз на
вызов) ⇒ заметно дешевле кватерниона.

## 3. Сопоставление моделей

| Критерий | Кватернион | Матрица Rx/Ry/Rz |
|----------|-----------|------------------|
| Операций на вершину | ~15–20 | ~6 |
| Гимбал-лок | отсутствует | возможен при композиции Эйлера |
| Композиция | произведение кватернионов | произведение матриц |
| Накопление ошибки | мала (нормировка) | требует реортогонализации |
| Интерполяция | SLERP (гладкая) | сложнее |
| Память | 4 числа | 9 чисел (полная 3×3) |

> Гипотеза H2 ([hypothesis.md](../01-research-analysis/hypothesis.md)): матрица
> быстрее кватерниона на той же вершине из-за меньшего числа операций — проверяется
> бенчмарком при фиксированном движке.

## 4. Точность: f32 против f64

- Rust-ядро выполняет все операции в `f32`.
- JS выполняет операции в `f64`, но **результат усекается до `f32`** при записи в
  `Float32Array`.

Поэтому численное расхождение результатов лежит на уровне округления `f32`
(`max |WASM − JS| ≈ 10⁻⁵…10⁻⁶`), что подтверждает идентичность моделей и
корректность сравнения (гипотеза H3).

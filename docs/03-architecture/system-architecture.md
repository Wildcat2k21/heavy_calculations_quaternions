# Архитектура системы

Проект построен как **трёхслойная вычислительно-визуальная система**. Слои
разделены по ответственности и направлению потока данных.

```
┌─────────────────────────────────────────────────────────────┐
│  Presentation Layer (UI / визуализация)                      │
│  • Vite + кастомный Component (src/utils/Component.js)        │
│  • Three.js Canvas, OrbitControls                            │
│  • Панель управления, переключатель движка, селектор модели  │
│  • Оверлей метрик, бенчмарк-сессия                           │
│  src/components/WebGL/index.js · Quaternion.js · Rotmat.js   │
├─────────────────────────────────────────────────────────────┤
│  Math-JS Layer (координация и состояние)                     │
│  • buildResultQuaternion()  — композиция кватернионов        │
│  • quatToAxisAngle()        — извлечение оси и угла          │
│  • updateUnits()            — анимация прогресса             │
│  • normalizeModel() / applyNormalize() — подготовка геометрии│
│  src/math/qut.js · mat.js · vec3.js · WebGL/lib/*            │
├─────────────────────────────────────────────────────────────┤
│  Compute Layer (движки вычислений, переключаемо)             │
│  rotate_vertices_axis_angle_inplace   [WASM | JS]            │
│  rot_by_rotmat_inplace                [WASM | JS]            │
│  rotation-core/src/lib.rs   ←→   src/math/rotations-js.js    │
└─────────────────────────────────────────────────────────────┘
                              ↕
                  Float32Array (общий буфер вершин)
                              ↕
              THREE.BufferGeometry → GPU → WebGL
```

## Слой представления (Presentation)

Отвечает за интерфейс и рендеринг:

- **сцена и рендеринг** — `initScene.js` (Scene, PerspectiveCamera,
  WebGLRenderer, OrbitControls);
- **панель управления** — добавление узлов вращения (`Quaternion`, `Rotmat`),
  очистка, переключатель **WASM/JS**, селектор модели, кнопка бенчмарка;
- **оверлей метрик** — движок, FPS, время кадра, число вершин;
- **бенчмарк-сессия** — оркестрация прогона и вывод таблицы/отчёта.

Тонкий собственный класс `Component` обеспечивает шаблонизацию, монтаж и простую
событийную модель (без внешнего фреймворка).

## Слой координации (Math-JS)

«Склейка» между UI и вычислительным ядром:

- собирает состояние узлов вращения и **строит результирующее преобразование**
  (`buildResultQuaternion` → `quatToAxisAngle`);
- анимирует прогресс угла (`updateUnits`);
- готовит геометрию: центрирование и масштаб (`normalizeModel`,
  `applyNormalize`).

Вспомогательные математические типы (`Quat`, `Vec3`, `Mat`) живут в `src/math/`.

## Слой вычислений (Compute)

Ядро вращения вершин в двух взаимозаменяемых реализациях:

| Операция | WASM (Rust) | JS-fallback |
|----------|-------------|-------------|
| Кватернион (axis-angle) | `rotate_vertices_axis_angle_inplace` | `rotateVerticesAxisAngleJS` |
| Матрица Rx/Ry/Rz | `rot_by_rotmat_inplace` | `rotByRotmatJS` |

Выбор реализации — по флагу `engineMode`. Обе работают **inplace** над общим
`Float32Array`. Это единственное место, которое **различается** между режимами —
поэтому именно его время измеряет бенчмарк.

## Принцип «единой точки переключения»

В `WebGL/index.js` введены диспетчеры `rotateQuat()` и `rotateMat()`, скрывающие
выбор движка. Благодаря этому остальной код (анимация, метрики, бенчмарк) не
зависит от того, какой движок активен, и сравнение остаётся честным.

## Чего в архитектуре намеренно нет

- серверной части, REST API, базы данных;
- аутентификации и ролей;
- контейнеризации.

Это статический фронтенд + WASM — см.

# Обзор предметной области: вращения в 3D

## Способы представления вращения

В трёхмерной графике вращение твёрдого тела представляют несколькими способами.
Каждый имеет свои достоинства и недостатки.

### 1. Углы Эйлера (Euler angles)

Три угла поворота вокруг осей (pitch, yaw, roll). Интуитивны, но страдают от
**гимбал-лока** (потеря степени свободы при совпадении осей) и зависят от порядка
применения. В проекте напрямую **не используются**.

### 2. Матрицы поворота (Rotation Matrix)

Поворот задаётся ортогональной матрицей 3×3. Базовые повороты вокруг осей:

```
        | 1    0      0   |          | cosθ  0  sinθ |          | cosθ -sinθ 0 |
Rx(θ) = | 0  cosθ  -sinθ  |  Ry(θ) = |  0    1   0   |  Rz(θ) = | sinθ  cosθ 0 |
        | 0  sinθ   cosθ  |          |-sinθ  0  cosθ |          |  0     0   1 |
```

- **Плюсы:** прямое применение к вектору `v' = R·v`, привычность.
- **Минусы:** избыточность (9 чисел на 3 степени свободы), накопление ошибки
  ортогональности при композиции, гимбал-лок при последовательных Эйлеровых
  поворотах.

> В проекте матрицы реализованы как поворот вокруг одной координатной оси
> (Rx/Ry/Rz) — функция `rot_by_rotmat_inplace`.

### 3. Ось-угол (Axis-Angle)

Вращение задаётся единичной осью **û** и углом θ. Компактно (4 числа), наглядно.
Служит базовой формой для построения кватерниона.

### 4. Кватернионы (Quaternion)

Гиперкомплексное число `q = w + xi + yj + zk`, где единичный кватернион кодирует
вращение:

```
q = ( cos(θ/2),  û·sin(θ/2) )
```

Поворот вектора `v`:  `v' = q · v · q*` (где `q*` — сопряжённый).
В проекте используется эквивалентная **формула Родрига** без явного умножения
кватернионов:

```
v' = v + 2·( q_w·(u × v) + u × (u × v) )
```

- **Плюсы:** нет гимбал-лока; компактная композиция (`q = q₁·q₂·…·qₙ`); устойчивая
  нормализация; гладкая интерполяция (SLERP).
- **Минусы:** менее интуитивны для человека.

## Композиция вращений

- **Кватернионы:** последовательность вращений = произведение кватернионов
  `q_final = q₁·q₂·…·qₙ`, затем единый поворот всех вершин (реализовано в
  `buildResultQuaternion()` + `quatToAxisAngle()`).
- **Матрицы:** последовательное применение `v' = Rₙ·…·R₂·R₁·v`.

## Применение к геометрии

Модель хранится как набор вершин и рёбер. Для отрисовки каркаса (wireframe)
рёбра разворачиваются в плоский массив `Float32Array` вида
`[x₁,y₁,z₁, x₂,y₂,z₂, …]`, который поворачивается **inplace** и передаётся на GPU
через `THREE.BufferGeometry`.

## Почему это важно для производительности

Вращение применяется к **каждой** вершине **каждый** кадр. При 60 кадрах/с и
сотнях тысяч вершин это миллионы операций в секунду — типичная «горячая точка»,
на которой и проявляется разница между WASM и JS, кватернионом и матрицей.
Именно эту разницу измеряет стенд (см. [05-benchmark](../05-benchmark/README.md)).

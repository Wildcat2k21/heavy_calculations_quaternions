# Анализ существующих решений (аналоги)

Цель — показать, где в реальных продуктах применяются сравниваемые подходы, и чем
исследовательский стенд отличается от готовых библиотек.

## Сравнительная таблица

| Решение | Модель вращения | Движок вычислений | Открытость замеров |
|---------|-----------------|-------------------|--------------------|
| **Three.js** | Кватернионы (`THREE.Quaternion`) + матрицы (`Matrix4`) | JavaScript (частично WASM в аддонах) | Нет встроенного сравнения |
| **Babylon.js** | Кватернионы + матрицы | JavaScript; WASM для физики (Ammo/Havok) | Нет |
| **Unity** | Кватернионы (`Quaternion`) | Нативный C++ / C# (Burst+SIMD) | Внутренние профайлеры |
| **glMatrix** | Матрицы и кватернионы | Чистый JavaScript (оптимизирован под JIT) | Микробенчмарки в репозитории |
| **gl-matrix + wasm-эксперименты** | Матрицы/кватернионы | WASM | Разрозненные статьи |
| **Наш стенд** | Кватернион **и** матрица, переключаемо | **WASM и JS, переключаемо** | **Встроенная бенчмарк-сессия** |

## Краткий разбор

### Three.js
Базовая библиотека рендеринга для веба. Использует кватернионы как внутреннее
представление поворота объектов (`Object3D.quaternion`). Вся математика — на JS.
WASM встречается лишь в отдельных загрузчиках/декодерах (например, DRACO). Прямого
сравнения «WASM vs JS» для вращения не предоставляет. В проекте Three.js
используется **только для рендеринга** (см. [04/rendering.md](../04-implementation/rendering.md)).

### Babylon.js
Полноценный игровой движок для веба. Богатый математический модуль на JS; WASM
применяется в физических подсистемах (Ammo.js, Havok). Вращения объектов —
кватернионные, считаются на JS.

### Unity
Промышленный движок. Кватернионы — основной API вращений. Высокая
производительность достигается нативным кодом и системой Burst (LLVM + SIMD).
Это «золотой стандарт» по скорости, но вне браузера и закрытый.

### glMatrix
Минималистичная JS-библиотека линейной алгебры, тщательно оптимизированная под
JIT-движки V8/SpiderMonkey (избегает аллокаций, использует typed arrays). Хороший
ориентир «насколько быстрым может быть чистый JS».

## Ниша исследовательского стенда

Готовые библиотеки **фиксируют** выбор движка и модели вращения и **не дают**
встроенного инструмента для их сравнения на одинаковой нагрузке. Наш стенд:

1. реализует **обе** модели вращения и **оба** движка с переключением «на лету»;
2. гарантирует **идентичность алгоритмов** (JS-fallback — построчный аналог Rust);
3. предоставляет **воспроизводимую методику замера** (300 кадров, прогрев,
   статистика, проверка корректности);
4. экспортирует результаты в готовый для оформления текстовый формат.

Именно это сочетание делает работу **исследовательской**, а не очередной
обёрткой над существующей библиотекой.

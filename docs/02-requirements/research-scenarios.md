# Сценарии экспериментов (аналог Use Case)

Актор — **Исследователь** (единственный пользователь стенда). Каждый сценарий
описывает путь получения измеримого результата.

## Карта сценариев

```
            ┌──────────────────────────────────────────┐
            │                Исследователь             │
            └──────────────────────────────────────────┘
              │        │            │             │
              ▼        ▼            ▼             ▼
        ЭКС-1     ЭКС-2        ЭКС-3         ЭКС-4
   визуальная  переключение  замер метрик  бенчмарк-
    проверка    движка        в реальном   сессия
   вращения    WASM/JS        времени      (4 режима)
                                  │
                                  ▼
                              ЭКС-5
                        масштабируемость
                        (смена модели)
```

---

## ЭКС-1. Визуальная проверка вращения

- **Цель:** убедиться, что обе модели вращения работают корректно визуально.
- **Шаги:**
  1. Открыть стенд.
  2. Нажать «Через ось r» — добавить кватернионное вращение; задать ось и
     диапазон угла.
  3. Нажать «Матрица поворота…» — переключиться на матричное вращение (Rx/Ry/Rz).
  4. Наблюдать анимацию и стрелку оси результирующего вращения.
- **Результат:** модель плавно вращается; ось отображается корректно.

## ЭКС-2. Переключение движка WASM ↔ JS

- **Цель:** сравнить «на глаз» отзывчивость при одинаковом вращении.
- **Шаги:**
  1. Запустить вращение (ЭКС-1).
  2. Нажать кнопку **«Движок: WASM/JS»** — переключить движок.
  3. Сравнить значение «Кадр (compute)» в оверлее метрик.
- **Результат:** время кадра меняется при смене движка; визуальный результат
  идентичен.

## ЭКС-3. Замер метрик в реальном времени

- **Цель:** снять мгновенные показатели нагрузки.
- **Шаги:**
  1. Запустить вращение.
  2. Считать из оверлея: **движок**, **FPS**, **время кадра (мс)**, **число
     вершин**.
- **Результат:** актуальные метрики на текущей модели и движке.

## ЭКС-4. Бенчмарк-сессия (ключевой сценарий)

- **Цель:** получить воспроизводимые количественные данные для сравнения.
- **Предусловие:** выбрана модель.
- **Шаги:**
  1. Нажать **«▶ Запустить бенчмарк»**.
  2. Дождаться прогона 300 кадров для 4 сочетаний:
     `{Кватернион, Матрица} × {WASM, JS}`.
  3. Изучить итоговую таблицу (FPS, min/max/avg время кадра), коэффициент
     ускорения и проверку корректности `max |WASM − JS|`.
  4. Нажать **«Копировать в буфер обмена»** — получить текстовый отчёт сессии.
- **Результат:** заполненная таблица + текстовый блок формата
  `=== BENCHMARK SESSION ===` для оформления в
  [05-benchmark](../05-benchmark/README.md).

## ЭКС-5. Исследование масштабируемости

- **Цель:** оценить деградацию производительности с ростом числа вершин.
- **Шаги:**
  1. В селекторе модели выбрать `model.json` (≈ 51 тыс. вершин буфера) — запустить
     ЭКС-4.
  2. Выбрать `model.h.json` (≈ 327 тыс. вершин буфера) — повторить ЭКС-4.
  3. Сравнить коэффициенты ускорения и абсолютное время кадра между моделями.
- **Результат:** данные для графика деградации и вывода о линейности сложности.

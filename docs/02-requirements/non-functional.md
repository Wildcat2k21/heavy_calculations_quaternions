# Нефункциональные требования

| ID | Категория | Требование | Как проверяется |
|----|-----------|-----------|-----------------|
| **NFR-1** | Производительность | Интерактивная работа ≥ 60 FPS на `model.json` в режиме WASM | Оверлей FPS, бенчмарк |
| **NFR-2** | Производительность | Время кадра (compute) измеримо и сглажено (EMA) | Оверлей «Кадр (compute)» |
| **NFR-3** | Точность | Расхождение JS и WASM не превышает предела `f32` (`< 10⁻³`) | `max |WASM − JS|` в бенчмарке |
| **NFR-4** | Воспроизводимость | Бенчмарк фиксирован: 300 кадров, прогрев 30, единый набор сочетаний | Код `measure()` |
| **NFR-5** | Память | Inplace-вращение без аллокаций на кадр | Архитектура ядра |
| **NFR-6** | Переносимость | Работает в современном браузере с поддержкой WASM и WebGL | Ручная проверка |
| **NFR-7** | Развёртывание | Статическая сборка `npm run build`, без серверной части и БД | CI/локально |
| **NFR-8** | Сопровождаемость | Чёткое разделение слоёв (UI / Math-JS / Compute) | См. [03-architecture](../03-architecture/README.md) |
| **NFR-9** | Корректность кода | Rust-ядро проходит `cargo clippy` без предупреждений | `cargo clippy` |

## Комментарии

### NFR-1 / NFR-2 — производительность
Целевой порог 60 FPS — стандарт реального времени. На детальной модели
(`model.h.json`, ~327 тыс. вершин) FPS в живом режиме ограничен браузером (vsync),
поэтому **различающей метрикой служит время кадра (мс)**, а не FPS. Бенчмарк
снимает время блока вычислений без vsync-ограничения.

### NFR-3 — точность
Rust считает в `f32`, JS — в `f64` с усечением до `f32` при записи в
`Float32Array`. Цель — убедиться, что разница лежит в пределах округления `f32`,
то есть сравнивается **одна и та же математика**.

### NFR-7 — развёртывание
Проект сознательно остаётся статическим фронтендом + WASM. Отсутствие БД, REST и
контейнеров — не недоработка, а архитектурное решение (см.
[план приведения проекта, п. 6.3](../../Приведение%20проекта%20в%20траектории%20Исследования.md)).

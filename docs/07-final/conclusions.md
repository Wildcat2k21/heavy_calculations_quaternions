# Выводы по исследованию

По результатам двух бенчмарк-сессий (23.06.2026, Firefox 149 / Ubuntu Linux) на
моделях `model.json` (50 970 верш.) и `model.h.json` (326 786 верш.).
Исходные данные — [05-benchmark/comparison.md](../05-benchmark/comparison.md).

## 1. Проверка гипотез

| Гипотеза | Формулировка | Вердикт | Числовое обоснование |
|----------|--------------|---------|----------------------|
| **H1** | WASM быстрее JS, выигрыш растёт с N | ✅ / 🟡 **уточнена** | WASM быстрее везде (×1.25–1.56); рост с N — для матрицы (×1.33→×1.56), у кватерниона стабильно (×1.29→×1.25) |
| **H2** | Матрица дешевле кватерниона | ✅ **подтверждена** | матрица дешевле во всех 4 случаях на 12–30 % |
| **H3** | JS идентичен WASM (в пределах f32) | ✅ **подтверждена** | `max |WASM−JS| ≈ 10⁻⁷` (6·10⁻⁸ … 2.4·10⁻⁷) |
| **H4** | Время кадра линейно по N | ✅ **подтверждена** | рост времени ×6.4 при росте вершин ×6.41 |
| **H5** | Есть порог окупаемости WASM | ❌ **опровергнута** (в диапазоне) | WASM выгоден уже при 50k вершин; порог, если есть, ниже исследованного диапазона |

## 2. Главный вывод

**Нативное WASM-ядро (Rust) устойчиво превосходит эквивалентный JavaScript** на
вращении больших массивов вершин — на 25–56 % по среднему времени кадра — при
**полной идентичности** математического результата (расхождение на уровне
округления `f32`). Наилучшее сочетание по скорости — **WASM + матрица**; наиболее
универсальное по функциональности — **WASM + кватернион** (композиция,
интерполяция, отсутствие гимбал-лока).

Разрыв на конкретном кадре умеренный (современный JIT Firefox силён), однако
**удельное** преимущество WASM компаундится: в бюджете 60 FPS WASM удерживает
сцену на **+0.9 … +2.4 млн вершин** крупнее, чем чистый JS
(см. [05-benchmark/wasm-potential.md](../05-benchmark/wasm-potential.md)).

## 3. Практические рекомендации

- **WASM** — для тяжёлой геометрии (10⁵–10⁷ вершин), запаса на 60/120 FPS и слабых
  устройств (где JIT менее агрессивен). Потенциал ещё выше при SIMD.
- **Чистый JS** — для лёгких сцен (< 50k вершин) и простоты поставки без
  Rust-тулчейна; разрыв остаётся в пределах ~25–35 %.
- **Матрица** — простые одноосевые повороты (дешевле); **кватернион** — композиция,
  интерполяция, устойчивость к гимбал-локу.

## 4. Коммерческая применимость

Ядро вращения — переиспользуемый компонент для 3D-редакторов, CAD-вьюеров и
браузерных симуляторов. Переключаемость движка позволяет подбирать баланс
«скорость ↔ совместимость» под целевые устройства, а замер потенциала показывает
запас масштабирования на миллионы вершин.

## 5. Ограничения и направления развития

- **Точность таймера.** Firefox округляет `performance.now()` до 1 мс — абсолютные
  значения зашумлены (средние по 300 кадрам репрезентативны, относительные выводы
  устойчивы). Развитие: замер в нескольких браузерах/на нескольких машинах.
- **Диапазон моделей.** Две модели; для точного графика деградации добавить
  промежуточные (1k/5k/10k/20k вершин) и подтвердить отсутствие порога H5.
- **SIMD / WebGPU.** Перспектива: SIMD-версия WASM-ядра и сравнение с WebGPU
  compute — ожидается кратный рост отрыва.

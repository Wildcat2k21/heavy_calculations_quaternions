# Техническая записка

## 1. Общие сведения

Данный проект представляет собой веб-приложение для интерактивной визуализации трёхмерных вращений объектов с использованием библиотеки **Three.js** и вычислительного модуля на базе **WebAssembly (Rust)**.

Система разработана для анализа и сравнения различных математических моделей вращения:
- кватернионы (axis-angle → quaternion composition)
- матрицы вращения (Rx, Ry, Rz)
- представление вращения в виде ось-угол

---

## 2. Архитектура системы

Архитектура проекта разделена на три основных слоя:

### 2.1. Клиентская часть (JavaScript + Three.js)
Отвечает за:
- создание 3D-сцены
- загрузку модели
- управление камерой
- визуализацию геометрии
- обработку пользовательского ввода
- отрисовку стрелок осей вращения

Используемые компоненты:
- Three.js (WebGL рендеринг)
- OrbitControls (управление камерой)
- BufferGeometry (хранение вершин)

---

### 2.2. Математический слой (JavaScript)
Отвечает за:
- работу с кватернионами
- композицию вращений
- преобразование quaternion → axis-angle

Основные сущности:
- `Quat` — реализация кватерниона
- `Vec3` — векторная математика
- `buildResultQuaternion()` — композиция вращений
- `quatToAxisAngle()` — извлечение оси и угла

---

### 2.3. Вычислительный слой (Rust → WebAssembly)

Реализует высокопроизводительные операции над массивами вершин:

#### Основные функции:
- `rotate_vertices_axis_angle_inplace`
- `rot_by_rotmat_inplace`

#### Особенности реализации:
- работа напрямую с `Float32Array`
- inplace-модификация (без создания новых буферов)
- минимизация аллокаций памяти
- SIMD-оптимизация (при наличии поддержки)

---

## 3. Поток обработки данных

1. Загружается 3D-модель (JSON)
2. Модель нормализуется (центрирование и масштабирование)
3. Формируется массив вершин (`Float32Array`)
4. Инициализируется WebAssembly модуль
5. В каждом кадре:
   - обновляется состояние вращений
   - вычисляется итоговое вращение
   - применяется трансформация к вершинам
   - обновляется GPU buffer (Three.js)

---

## 4. Модели вращения

### 4.1. Кватернионная модель (rmethod = 1)

- каждое вращение задаётся осью и углом
- итоговое вращение:
  \[
  q_{final} = q_1 \cdot q_2 \cdot ... \cdot q_n
  \]

- применяется преобразование:
  - quaternion → axis-angle
  - затем вращение вершин через WASM

---

### 4.2. Матричная модель (rmethod = 2)

- используется последовательное применение вращений
- каждое вращение:
  - Rx / Ry / Rz
- применяется напрямую в массив вершин:

\[
v' = R_n \cdot ... \cdot R_2 \cdot R_1 \cdot v
\]

---

## 5. Оптимизация производительности

Основные оптимизации:

### 5.1. Inplace вычисления
- исключение лишних аллокаций памяти
- повторное использование Float32Array

### 5.2. WebAssembly
- перенос вычислительно тяжёлых операций в Rust
- снижение нагрузки на JavaScript GC

### 5.3. Минимизация обновлений GPU
- обновление BufferAttribute только после изменения массива

## 6. Графическая подсистема

Используется Three.js:

- `Scene` — контейнер сцены
- `Camera` — перспективная камера
- `Renderer` — WebGL рендеринг
- `LineSegments` — отображение каркаса модели
- `ArrowHelper` — визуализация осей вращения

- модель может быть масштабирована независимо от сцены

Разработанная система демонстрирует эффективную интеграцию WebAssembly и WebGL для решения задач трёхмерной визуализации и математического моделирования вращений.

Архитектура позволяет масштабировать систему за счёт разделения:

## 🏗️ АРХИТЕКТУРА PCMEF — КЛЮЧЕВАЯ КОНЦЕПЦИЯ

Все проекты обязаны использовать архитектурный паттерн **PCMEF**.

| Слой | Название | Ответственность | НЕ ДОЛЖЕН |
|------|----------|-----------------|-----------|
| **P** | Presentation (Представление) | UI, отображение, ввод пользователя | Содержать бизнес-логику |
| **C** | Control (Управление) | Обработка запросов, валидация | Обращаться к БД напрямую |
| **M** | Mediator (Посредник) | Бизнес-логика, транзакции, правила | Знать о Presentation |
| **E** | Entity (Сущность) | Бизнес-объекты, состояние, методы предметной области | Содержать логику доступа к данным |
| **F** | Foundation (Фундамент) | Доступ к данным, SQL, репозитории | Содержать бизнес-правила |

### Правило зависимостей (СТРОГО):
```
P → C → M → E → F
```
Зависимости направлены **только сверху вниз**. Нижние слои **НЕ ЗНАЮТ** о верхних.  
Нарушение этого правила = **штраф -20%**.

### Обязательные интерфейсы между слоями:

**Control → Mediator (IService):**
```java
public interface IUserService {
    User getUserById(Long id);
    User createUser(User user);
    User authenticate(String email, String password);
    List<User> getAllUsers();
}
```

**Mediator → Foundation (IRepository):**
```java
public interface IUserRepository {
    User findById(Long id);
    User save(User user);
    void delete(Long id);
    User findByEmail(String email);
}
```

### Шаблон PlantUML для диаграммы пакетов PCMEF:
```plantuml
@startuml
allowmixing
title Архитектура PCMEF

interface "IUserService" as IUS
interface "IUserRepository" as IUR

package "Presentation" { rectangle "MainWindow" as P }
package "Control" {
    rectangle "UserController" as C
    C --> IUS : uses
}
package "Mediator" {
    rectangle "UserService" as M
    M ..|> IUS : implements
    M --> IUR : uses
}
package "Foundation" {
    rectangle "UserRepository" as F
    F ..|> IUR : implements
}
database "Database" as DB
F --> DB : JDBC
@enduml
```
